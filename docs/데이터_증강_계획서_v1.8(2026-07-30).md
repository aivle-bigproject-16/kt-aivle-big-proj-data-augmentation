### 1.4 수량 배정 규칙

1. 원본 image–JSON 1:1 pair를 canonical 상대경로 순으로 정렬한다.
2. 고정 seed `20260723`으로 모달리티별 후보 순서를 결정한다.
3. 최종 output slot을 CT 20,000개, RGB 20,000개 먼저 만든다.
4. output slot에 PASS/FAIL, main/test, failure case, 신규 ID, item seed를 먼저 고정한다.
5. 선택 source가 케이스 전제조건이나 자동 검증을 통과하지 못하면 같은 failure case의 다음 reserve source가 slot을 승계한다.
6. reserve source는 최종 slot으로 승격되기 전에는 신규 ID를 발급받지 않는다.
7. 전체 실행에서 `consumed_source_keys` set을 유지한다. plan에 배정됐거나 reserve 승격으로 사용된 source key는 다른 slot의 선택·reserve 후보에서 제외한다.
8. source key는 `(raw_split.casefold(), stem.casefold())`다.
9. 다른 failure case로 임의 재배정하지 않는다.
10. case quota와 최종 수량이 정확히 일치하지 않으면 전체 실행을 실패 처리한다.

## 2. 증강법

### 2.1 공통 입력 및 좌표 계약

#### CT

1. 원본 이미지와 같은 stem의 JSON을 읽는다.
2. ROI는 `data_info.roi`를 우선 사용하고, 없으면 `image_info.roi`를 legacy fallback으로 사용한다.
3. ROI 형식은 `[roi_width, roi_height]`다.
4. CT 이미지에서 `(0, 0, roi_width, roi_height)`를 먼저 crop한다.
5. 모든 CT 증강은 ROI crop 결과에 적용한다.
6. CT가 RGB mode여도 R/G/B 채널에 서로 다른 색상 증강을 적용하지 않는다.

#### RGB

1. 전체 원본 프레임을 사용한다.
2. battery mask는 `swelling.battery_outline` polygon을 rasterize해 만든다.
3. outline bbox, 장축, 면적, 내부 luminance 통계는 이 mask를 기준으로 계산한다.

#### 좌표

- 입력 polygon은 평탄 배열 `[x1, y1, x2, y2, ...]`을 기본으로 지원한다.
- 기하 증강은 이미지와 `battery_outline`, `defects[].points`에 동일한 변환을 적용한다.
- 비기하 증강은 polygon을 이동시키지 않고 최종 resize scale만 적용한다.
- crop 후 polygon은 frame으로 clipping한다.
- clipping 결과가 3개 미만의 점 또는 0 면적이면 해당 polygon을 제거한다.
- 원본 JSON 파일은 수정하지 않는다.

#### 최종 이미지 공통 처리

```yaml
resize_long_side: 512
keep_aspect_ratio: true
allow_upscale: false
image_format: JPEG
jpeg_quality: 90
jpeg_subsampling: 0
jpeg_optimize: false
jpeg_progressive: false
```

- 증강은 원본 또는 CT ROI 해상도에서 적용하고 resize는 마지막에 한 번만 수행한다.
- 모든 공간 파라미터는 **512-normalized 공간**에서 정의한다. 입력이 512보다 작아 확대하지 않는 경우에도 분모는 실제 출력 길이가 아니라 512를 사용한다.

```text
source_value = normalized_512_value × source_long_side / 512
```

- 현재 CT 4000px와 RGB 1920px 원본은 모두 512보다 크므로 실제 출력에서 `normalized_512_value`와 동일한 크기로 나타난다.

#### 난수와 재현성

난수 구현은 NumPy `Generator(PCG64)`로 고정한다.

```python
from hashlib import sha256
import numpy as np

def seed64(text: str) -> int:
    return int.from_bytes(sha256(text.encode("utf-8")).digest()[:8], "big")

item_seed = seed64(f"{global_seed}|{synthetic_id}")
case_seed = seed64(f"{item_seed}|{failure_case}")
rng = np.random.Generator(np.random.PCG64(case_seed))
```

분포 규칙:

- 별도 분포가 적혀 있지 않은 실수 범위 `a~b`는 `rng.uniform(a, b)`를 사용한다.
- 정수 범위 `a~b`는 양 끝을 포함하는 `rng.integers(a, b + 1)`을 사용한다.
- 확률 `p%`는 `rng.random() < p / 100`으로 결정한다.
- 목록 선택은 문서에 적힌 순서를 canonical order로 사용하고 균등 정수 index로 선택한다.
- 파라미터 draw 순서는 각 케이스의 구현 번호와 같은 순서다.
- retry는 같은 난수열을 되감지 않고 현재 RNG의 다음 값을 사용한다.
- reserve source가 slot을 승계하면 slot의 `item_seed`와 `case_seed`를 그대로 사용한다.

CT 연속 slice 그룹:

```text
group_key = (
  original_battery_id,
  axis
)
```

- frame 순서는 파일명 마지막 frame ID의 정수 오름차순이다.
- `group_seed = seed64(f"{global_seed}|{original_battery_id}|{axis}|{failure_case}")`로 계산한다.
- 방향, 회전 중심, 방사 중심 선택 규칙처럼 slice 간 유지해야 하는 값은 `group_seed`의 RNG로 한 번만 선택한다.
- sample별 강도 값은 각 slot의 `case_seed` RNG로 선택한다.
- `group_key`와 `group_seed`를 generation plan과 lineage에 기록한다.

### 2.2 CT 증강법

#### 2.2.1 `ct_cell_alignment_failure`

목적: 셀 또는 치구의 FOV 정렬 실패로 배터리 일부가 촬영 범위 밖에서 잘린 상태를 만든다. porosity 위치를 목표로 삼지 않는다.

적용 source:

- CT ROI와 유효한 `swelling.battery_outline`이 있어야 한다.
- porosity defect 존재 여부는 적격성 조건이 아니다.
- Plan 단계에서 outline 보유 source만 이 케이스에 배정하며, 부족하면 Generate 전에 중단한다.

구현:

1. 같은 battery ID·axis 그룹에서 상·하·좌·우 시작 방향을 한 번 정하고 그 순서로 gate-safe crop을 탐색한다.
2. 목표 outline 잔여율은 `0.60~0.82`에서 선택한다.
3. 선택 변을 1px부터 축 길이−1px까지 이분 탐색하며 방향당 최대 20회 outline 잔여 면적을 계산한다.
4. 한 축을 자르면 반대 축의 양쪽을 중앙 대칭으로 추가 crop하여 원본 ROI의 가로:세로 비율을 유지한다.
5. outline 잔여율 `0.50~0.90`인 첫 방향을 채택한다. 없으면 동일 case reserve로 재시도한다.
6. crop 결과를 LANCZOS로 원본 ROI raster 크기에 되돌린다. padding과 배경색 합성은 하지 않는다.
7. battery outline과 모든 defect polygon에는 crop 이동 후 원본 크기 복원 scale을 동일 affine 행렬로 적용하고 frame으로 clipping한다.

자동 통과 조건:

- outline 잔여 면적 비율 `0.50~0.90`
- 출력 raster 크기와 가로:세로 비율이 입력 ROI와 동일
- crop 면적이 0이 아니며 battery outline이 완전히 사라지지 않음
- porosity 유무와 무관하게 동작
- 고정 검정·진회색 padding 또는 이동으로 생긴 인공 배경 금지

기록 파라미터:

```json
{
  "type": "alignment_edge_crop",
  "direction": "left|right|top|bottom",
  "crop_box": [0, 0, 0, 0],
  "source_size": [0, 0],
  "output_size": [0, 0],
  "source_aspect_ratio": 0.0,
  "output_aspect_ratio": 0.0,
  "resize_to_source_size": true,
  "target_outline_retained_ratio": 0.0,
  "retained_outline_ratio": 0.0
}
```

#### 2.2.2 `ct_acquisition_motion`

목적: 촬영 중 심한 움직임으로 동일 CT 재구성 영상이 크게 어긋나 겹친 이중 영상을 만든다.

구현:

1. 원본 ROI 영상으로 약한 directional blur 영상을 만든다.
2. 동일 ROI 영상을 한 방향으로 평행이동한 ghost 영상을 만든다.
3. 두 영상을 다음 범위로 가중 합성한다.

```text
blurred_original weight: 0.48~0.55
shifted_original weight: 0.45~0.52
weights sum: 1.0
```

4. ghost offset 크기는 최종 512 공간에서 18~28px로 선택한다.
5. x/y 방향 성분은 하나의 방향 벡터에서 계산하며 같은 slice 그룹에서 방향을 유지한다.
6. directional blur 이동 범위는 최종 512 공간에서 ±2~5px다.
7. 인접 slice는 offset과 혼합비를 기준값의 ±10% 안에서만 변화시킨다.

자동 통과 조건:

- 원본과 출력의 raster, ROI, 좌표 frame이 동일
- 외피 또는 내부 구조에서 두 개의 분리된 edge peak가 검출됨
- 최종 512 공간 edge peak 간 거리가 18~28px
- 임의 직선, 가로 띠, crosshatch, 구조와 무관한 streak를 직접 그리지 않음
- 단순 Gaussian blur만 나타나는 결과 금지

이 케이스는 비기하 아티팩트로 취급한다. polygon 좌표는 이동하지 않는다.

#### 2.2.3 `ct_insufficient_projection_sampling`

목적: 투영 수 또는 투영 각도 부족으로 발생하는 구조 경계 기반 streak와 미세 구조 손실을 만든다.

내부 단계와 순서는 다음으로 고정한다.

```text
radon_projection_drop
→ filtered_back_projection
```

구현:

1. ROI grayscale을 정규화한다.
2. `radon_projection_drop` 단계에서 forward Radon transform으로 가상 sinogram을 생성한다.
3. `radon_projection_drop` 단계에서 다음 subtype 중 하나를 선택한다.

```text
sparse_view:
  전체 360°에서 균등한 각도만 20~45% 유지

limited_angle:
  연속된 60~120° 각도 구간을 제거
```

4. 누락된 각도는 0으로 채우지 말고 해당 투영 자체를 reconstruction 입력에서 제외한다.
5. `filtered_back_projection` 단계에서 ramp filter 기반 FBP로 원래 ROI 크기로 재구성한다.
6. 원본 저주파 밝기 범위에 맞게 percentile 1~99를 정규화한다.
7. `w_reconstruction = rng.uniform(0.75, 0.90)`으로 선택한다.
8. `w_original = 1.0 - w_reconstruction`으로 계산한다.
9. `output = w_reconstruction × reconstructed + w_original × original`로 혼합한다.

자동 통과 조건:

- 원본 구조 edge에서 시작하는 방향성 streak 존재
- 고주파 edge energy가 원본 대비 20~65% 감소
- 완전 단색 또는 outline 식별 불가 결과 금지
- 중심점에서 임의 방사형 선을 그리는 구현 금지
- `simulation_domain="reconstructed_slice_approximation"` 기록

이 케이스는 비기하 아티팩트다.

증강 이력의 `augmentations[].type`은 정확히 다음 두 문자열을 순서대로 사용한다.

```json
[
  {
    "order": 1,
    "type": "radon_projection_drop"
  },
  {
    "order": 2,
    "type": "filtered_back_projection"
  }
]
```

#### 2.2.4 `ct_low_signal_noise`

목적: 관전류 또는 노출시간 부족으로 photon 수가 감소한 저신호 CT를 만든다.

구현:

1. 입력 luminance를 `[0,1]`로 정규화한다.
2. intensity를 transmission 또는 photon count 공간으로 변환한다.
3. 기준 photon count를 `10~40` 범위로 낮춘다.
4. Poisson sampling을 적용한다.
5. 선택적으로 Poisson noise보다 약한 Gaussian read noise `sigma=0.005~0.025`를 추가한다.
6. 저대비 영역 contrast를 원본의 `0.45~0.80`으로 낮춘다.
7. CT가 3채널이면 동일한 noise field를 세 채널에 적용한다.

자동 통과 조건:

- 균일 영역 noise 표준편차가 원본보다 증가
- edge SNR이 원본 대비 20~65% 감소
- 전체 암전 금지
- RGB 채널 간 인공 색편차 증가 금지

이 케이스는 비기하 아티팩트다.

#### 2.2.5 `ct_beam_hardening_metal_streak`

목적: 고밀도 탭·집전체 주변의 beam hardening으로 넓은 cupping 왜곡과 밝고 어두운 reconstruction streak가 함께 나타나는 상태를 만든다.

구현:

1. ROI에서 상위 `0.3~1.0%` 고휘도 픽셀을 추출한다.
2. 연결 성분을 계산해 최소 면적을 만족하는 고밀도 anchor mask를 만든다.
3. anchor가 없으면 해당 source를 같은 케이스의 reserve source로 교체한다.
4. battery outline과 주 투과 방향을 기준으로 넓은 비대칭 타원형 cupping field를 만든다.
5. cupping field 중심은 고밀도 anchor와 연결하고 화면 중앙에 고정하지 않는다.
6. 타원 반경은 outline 짧은 변의 `35~70%`, 긴 변의 `12~30%`다.
7. field 내부 luminance 변화량은 8-bit 기준 `+35~+80` 또는 `-25~-10`이며 경계 feather 폭은 반경의 `8~18%`다.
8. 가장 강한 고밀도 연결 성분의 intensity-weighted centroid를 방사 중심점으로 선택한다.
9. 고밀도 영역이 여러 개면 임의로 여러 중심을 만들지 않고, 가장 강한 주 anchor 하나를 사용하거나 서로 가까운 성분을 하나의 anchor 영역으로 병합한다.
10. 주 anchor 중심에서 360° 전 방향으로 뻗는 starburst streak field를 만든다.
11. 방사선 수는 24~72개이며 각도 간격에 ±1~4° jitter를 적용해 기계적으로 균일한 부채꼴을 피한다.
12. 각 방사선 중심선은 anchor에서 시작해 frame 경계까지 계산한다.
13. 밝은 streak와 어두운 streak를 번갈아 사용하되 밝기·길이·폭·감쇠율을 서로 다르게 한다.
14. streak 폭은 최종 512 공간에서 1~4px, 시작부 alpha는 0.10~0.35다.
15. 중심에서 멀어질수록 강도가 감소하도록 exponential falloff `exp(-distance / tau)`를 적용하고 `tau`는 anchor부터 frame 경계까지 거리의 0.35~0.70으로 선택한다.
16. battery outline 밖 air 영역에서는 alpha를 0.08 이하로 제한하고, outline 경계부터 frame 경계까지 거리의 10~25% 안에서 0으로 감쇠한다.
17. 모든 방사선을 완전 직선·동일 길이로 만들지 않고 약한 blur와 국부 intensity 변동을 적용한다.
18. streak의 모든 중심선은 선택된 고밀도 anchor mask 또는 그 centroid와 교차해야 한다.

자동 통과 조건:

- 넓은 cupping 또는 reverse-cupping 영역이 육안으로 식별됨
- 선택된 고밀도 anchor 한 점 또는 작은 영역에서 360°로 퍼지는 starburst가 육안으로 식별됨
- 방사선 24~72개가 하나의 anchor와 연결되고 밝고 어두운 streak가 함께 존재함
- 0~90°, 90~180°, 180~270°, 270~360° 네 사분면 각각에 최소 4개 방사선이 존재함
- 가장 큰 비어 있는 각도 구간이 35° 이하임
- 완벽한 원, hard-edge spotlight, 화면 중심 고정 field 금지
- 서로 무관한 여러 시작점에서 선을 난사하는 형태 금지
- 평행선 묶음, 교차 격자, 균일 crosshatch 금지
- 고밀도 anchor가 아닌 임의 화면 좌표를 방사 중심으로 사용하는 구현 금지
- 원본 내부 구조가 완전히 포화되거나 사라진 결과 금지

이 케이스는 비기하 아티팩트다.

### 2.3 RGB 증강법

#### 2.3.1 `rgb_trigger_timing_failure`

목적: 컨베이어 트리거가 너무 빠르거나 늦어 배터리 앞·뒤 일부가 frame 밖으로 잘린 상태를 만든다.

필수 설정:

```yaml
conveyor_axis: horizontal|vertical
forward_direction: positive|negative
```

구현:

1. 앞 또는 뒤 방향을 50:50으로 선택한다.
2. battery outline 목표 잔여율을 `0.55~0.85`에서 선택한다.
3. 선택 방향의 배경 여백을 먼저 제거한다.
4. crop 선이 outline polygon과 교차하도록 누적 polygon 면적으로 crop 좌표를 계산한다.
5. 선택한 변에서 배터리를 자른 뒤 반대 축도 대칭 crop하여, crop 결과의 가로:세로 비율을 원본 이미지 비율과 같게 맞춘다.
6. 잘린 영역을 padding으로 복원하지 않으며 공통 resize에서도 이 종횡비를 유지한다.
6. 35% 확률로 컨베이어 축과 평행한 motion blur를 추가한다.
7. motion kernel은 최종 512 공간에서 5~17px 홀수다.

자동 통과 조건:

- outline 잔여 면적 비율 `0.50~0.90`
- crop 선과 outline 교차
- `abs(output_width / output_height - source_width / source_height) <= 0.02`
- 출력 outline이 선택한 frame 경계에 접촉
- 배경만 잘리고 배터리가 온전히 남은 결과 금지

이미지와 polygon에 같은 crop을 적용한다.

#### 2.3.2 `rgb_uneven_lighting`

목적: 일부 LED 고장 또는 조명 세기 불균일로 배터리 한쪽만 밝고 반대쪽이 어두운 상태를 만든다.

구현:

1. battery outline bbox를 기준으로 수평·수직 네 방향 `(0°, 90°, 180°, 270°)`을 case seed로 순환 탐색한다.
2. 각 방향에서 outline 투영 범위를 `[0,1]`로 정규화하고 `smoothstep(t)=t²(3−2t)`로 연속 조명 field를 만든다.
3. 아래 `(dark_gain, bright_gain)` 후보를 약한 순서부터 적용한다.

```text
(0.75,1.15), (0.65,1.15), (0.60,1.10), (0.60,1.20),
(0.55,1.25), (0.50,1.30), (0.45,1.35), (0.40,1.40),
(0.35,1.45), (0.25,1.65), (0.18,1.85), (0.12,2.05)
```

4. RGB 세 채널에 같은 gain field를 곱해 원본 색비를 보존한다.
5. outline 내부의 선택 축 양 끝 20% 평균으로 asymmetry를 계산하고 gate를 만족하는 첫 후보를 채택한다.
6. 50% 확률로 LED dead zone 1~3개를 시도한다. 각 면적은 outline의 4~18%, gain은 `0.20~0.65`이며 Gaussian field로 만든다. 추가 후 gate를 다시 만족할 때만 유지한다.

측정:

```text
object_asymmetry =
abs(mean(axis-low 20%) - mean(axis-high 20%))
/ mean(outline luminance)
```

자동 통과 조건:

- 출력 object asymmetry `0.25~0.60`
- 출력 asymmetry − 원본 asymmetry `>=0.15`
- frame 전체가 아니라 battery outline 내부에서 측정
- dead zone 추가 후에도 동일 조건 재검증
- 직선 경계 또는 배터리 전체가 균일하게 밝아지는 결과 금지

이 케이스는 비기하 아티팩트다.

#### 2.3.3 `rgb_reflection_glare`

목적: 직접광과 편광 억제 실패로 배터리 표면에 길고 부드러운 정반사 띠가 생겨 결함 식별을 방해하는 상태를 만든다.

적용 source:

- 유효한 battery outline이 있어야 하며 Plan 단계에서 적격 source만 배정한다.

구현:

1. outline 주성분으로 장축을 구하고 defect가 있으면 defect 중심·장축을 후보로 추가한다. defect가 없으면 기존 상위 18% 고휘도 영역, 그마저 없으면 outline 중심을 seed로 사용한다.
2. core는 1~2개의 선형 반사 띠로 만들며 장축 또는 그 수직축 후보를 탐색한다.
3. 길이 후보는 outline 장축 길이의 `8, 15, 25, 35, 50, 65, 80%`; 폭은 목표 면적으로 역산한 값의 `0.55, 0.75, 1.0, 1.25, 1.50배`다.
4. 띠의 길이:폭은 최소 `5:1`, core alpha는 `0.55~0.78`이다. 두 줄이면 폭의 1.8배 이상 간격으로 평행 배치한다.
5. core는 outline mask로 먼저 clipping한다. 목표 core 면적은 `max(outline×4.5%, defect×45%)`를 기본으로 하되 outline의 9%를 넘지 않는다.
6. 최종 512 공간 `5~14px` Gaussian bloom을 적용한 뒤 visible alpha를 outline으로 다시 clipping한다.
7. 색은 따뜻한 흰색 `(255,246,224)`으로 alpha 합성하며 불투명 직사각형을 그리지 않는다.
8. 가능한 후보 중 core 면적 5%, defect coverage 45%에 가장 가까운 geometry를 선택한다.

자동 통과 조건:

- core의 outline 내부 비율 `>=0.90`
- core가 outline 면적의 `1~12%`
- outline 내부 최종 포화율 `<=12%`
- defect가 있으면 coverage 하한은 `min(0.30, max(0.05, 0.01 / defect_object_ratio))`, 상한은 `0.70`
- 직사각형 막대, hard edge, 순백 불투명 blob, 배경으로 번지는 bloom 금지

기록 type은 `surface_aware_specular_reflection` 다음 `highlight_bloom` 순서다. 이 케이스는 비기하 아티팩트다.

#### 2.3.4 `rgb_focus_failure`

목적: 렌즈 초점 이탈로 작은 scratch와 표면 오염 경계가 식별되지 않는 상태를 만든다.

구현:

1. Gaussian defocus radius를 최종 512 공간 `2.5~10px`에서 선택한다.
2. source radius는 `radius_512 × source_long_side / 512`로 계산해 RGB 세 채널에 동일하게 적용한다.
3. motion blur는 혼합하지 않는다. 이 케이스의 기록 type은 `defocus_blur` 하나다.

자동 통과 조건:

- 원본과 출력을 최종 긴 변 512 좌표계로 맞춘 뒤 RMS gradient edge energy 비율 `0.25~0.75`
- battery outline은 식별 가능
- 완전 단색 또는 방향성 smear 금지

이 케이스는 비기하 아티팩트다.

#### 2.3.5 `rgb_underexposure`

목적: 광원은 켜져 있지만 노출시간 또는 sensor gain이 부족해 신호와 암부 SNR이 낮은 상태를 만든다.

구현:

1. sRGB를 linear-light 공간으로 변환한다.
2. 초기 linear exposure factor `0.18~0.40`을 적용한다.
3. photon capacity `80~220`으로 signal-dependent Poisson shot noise를 적용한다.
4. channel-correlated read noise `sigma=0.005~0.015`, 그 25% 크기의 chroma noise를 추가한다.
5. black level `0.003~0.012`를 차감한다.
6. outline 평균 목표 비율을 `0.44~0.56`에서 선택한다. 최대 3회 linear correction을 적용하되 각 correction은 `0.30~3.0`으로 제한한다.
7. correction은 outline 목표와 full-frame 평균 비율 상한 `0.68`을 동시에 만족하도록 둘 중 더 작은 scale을 사용한다.
8. camera tone curve로 sRGB에 되돌린다.

자동 통과 조건:

- outline 내부 평균 luminance 비율 `0.40~0.70`
- full-frame 평균 luminance 비율 `<=0.72`
- 8×8 저주파 frame의 원본·출력 조명 순위 상관계수 `>=0.95`
- 배경을 균일 회색으로 덮는 overlay와 전체 암전 금지

기록 type은 `linear_exposure_reduction`, `signal_dependent_shot_noise`, `sensor_read_noise` 순서이며 목표·실제 outline 비율, frame 비율과 correction을 기록한다. 이 케이스는 비기하 아티팩트다.

#### 2.3.6 `rgb_overexposure`

목적: 노출시간 과다 또는 조명 과강으로 밝은 표면 정보가 포화된 상태를 만든다.

구현:

1. sRGB를 linear-light로 변환하고 exposure factor `1.45~2.60`을 적용한 뒤 sRGB로 되돌린다.
2. outline 내부 목표 포화율을 `0.25~0.60`에서 선택한다.
3. outline 내부 luminance 상위 픽셀을 목표 개수만큼 정확히 선택해 RGB를 255로 만든다.
4. 선택되지 않은 outline 픽셀은 최대 249로 제한하여 목표 포화 core가 결정적으로 유지되게 한다.
5. 50% 확률로 최종 512 공간 `3~18px` Gaussian bloom을 20% 혼합한다.
6. bloom 뒤 선택 core를 다시 255로 적용하고 나머지 outline 픽셀은 다시 249 이하로 제한한다.

자동 통과 조건:

- outline 내부 측정 포화율 `0.15~0.75`
- 출력 평균 luminance가 원본보다 큼
- full-frame 98% 이상 포화 금지
- 배경만 포화되고 배터리 정보가 그대로인 결과 금지

기록 type은 `overexposure`, 선택 시 `highlight_bloom` 순서다. 이 케이스는 비기하 아티팩트다.

#### 2.3.7 `rgb_surface_dust`

렌즈 또는 보호유리에 붙은 먼지가 초점 이탈된 음영으로 촬영된 상태를 만든다. 배터리 표면 먼지는 생성하지 않는다.

구현:

1. 카메라 frame 좌표에서 기본 1~3개, 최대 4개의 중심을 선택한다.
2. battery outline과 무관하게 배치하되 결과 중 최소 하나는 검사 영역과 겹치게 한다.
3. core 지름은 최종 긴 변의 1~6%다.
4. core는 회갈색 또는 회색의 불규칙 저대비 blob이다.
5. core alpha는 `0.05~0.20`이다.
6. core 반경의 `1.5~3.5배`인 넓은 Gaussian halo를 추가한다.
7. halo alpha는 `0.03~0.10`이다.
8. 동일 크기·동일 모양을 반복하지 않는다.
9. 카메라 plane 좌표에 고정하며 배터리 이동에 따라 오염이 움직이지 않는다.

자동 통과 조건:

- 오염 수 1~4개
- 넓고 흐린 halo 존재
- 선명한 원, 다수 점박이, 배터리 표면에 붙은 입자처럼 보이는 결과 금지

이 케이스는 비기하 아티팩트다.

#### 2.3.8 `rgb_hair_contamination`

렌즈 또는 보호유리에 붙은 머리카락·섬유가 초점 이탈된 음영으로 촬영된 상태를 만든다.

구현:

1. 이미지당 기본 1개, 최대 2개의 curve를 만든다.
2. 길이는 최종 긴 변의 15~60%다.
3. 60~80% 확률로 frame 경계에서 시작한다.
4. 중심선 두께는 최종 긴 변의 0.15~0.6%다.
5. 양 끝에 taper를 적용한다.
6. 중심선보다 `2~5배` 넓은 Gaussian shadow를 만든다.
7. 중심 alpha는 `0.05~0.18`, halo alpha는 `0.02~0.10`이다.
8. 선명한 단색 선을 직접 출력하지 않고 모든 layer에 defocus blur를 적용한다.
9. 카메라 plane 좌표에 고정한다.

자동 통과 조건:

- 가변 두께, taper, 넓은 흐린 shadow 존재
- 선명한 1~3px Bézier 선 금지
- 화면 대부분을 가리는 curve 금지
- 동일한 curve 반복 금지

이 케이스는 비기하 아티팩트다.

### 2.4 증강 이력 공통 규칙

- FAIL 이미지당 failure case는 정확히 하나다.
- 한 failure case 내부의 연동 단계만 여러 개 사용할 수 있다.
- `failure_case_count`는 항상 1이다.
- `augmentation_count`는 실제 실행한 내부 단계 수다.
- seed, 선택 subtype, 실제 source-space/final-space 파라미터, mask 요약과 자동 검증 수치를 기록한다.
- 촬영 아티팩트 자체를 원본 `defects`에 새 defect로 추가하지 않는다.

### 3.3 파일명

```text

```

```text
RGB_cell_<form>_<new_battery_id>_<new_image_id>.jpg
```

- 원본의 modality, form, axis 구조는 유지한다.
- battery ID와 image/frame ID만 신규 값으로 치환한다.
- 이미지, 대응 JSON, augmentation JSON은 같은 stem을 사용한다.

ID 범위:


- 모든 출력 이미지는 서로 다른 신규 image ID를 사용한다.
- 기존 raw JSON의 ID와 충돌하면 자동 보정하지 않고 실행을 중단한다.

### 3.4 대응 라벨 JSON

원본 라벨 JSON을 deep copy한 뒤 다음만 갱신한다.

- `image_info.id`
- `image_info.file_name`
- `image_info.width`
- `image_info.height`
- 신규 battery ID가 저장된 기존 battery ID 필드
- crop/resize 이후 `swelling.battery_outline`
- crop/resize 이후 `defects[].points`
- 최상위 `quality_class`

```json
{
  "quality_class": "pass"
}
```

또는

```json
{
  "quality_class": "fail"
}
```

- 새 품질 필드는 `quality_class` 하나만 추가한다.
- `defects=null`은 출력에서 빈 배열 `[]`로 canonicalize한다.
- 공개 대응 JSON에는 원본 절대경로를 기록하지 않는다.

## 4. 파이프라인 순서

### 4.1 전체 순서

```text
1. validate configuration
2. scan raw-root read-only
3. pair image and JSON
4. preflight schema/decode
5. full source audit
6. build eligible pools
7. allocate 40,000 output slots and quotas
8. write deterministic generation plan
9. generate PASS and FAIL outputs
10. run per-sample automatic checks
11. promote staging files atomically
12. write manifests and summary
13. verify final counts/hashes
14. create augmentation JSON ZIP
```

### 4.3 raw-root 스캔

초기 원본 검증 결과는 schema v3인 `manifests/scan_cache.csv`에 저장한다. v3의
`has_battery_outline`은 polygon repair와 frame clip 후 양의 면적이 남는다는 뜻이다.
이전 v1/v2 캐시는 재사용하지 않는다. 이후 `--reuse-scan`
또는 `run_pipeline.ps1`의 대응 옵션으로 기존 캐시를 지정하면 파일 크기와
`mtime_ns`가 일치하는 image–JSON pair의 decode, schema 검사, SHA-256 및 pixel hash
계산 결과를 재사용한다. 변경되었거나 캐시에 없는 pair만 다시 검증한다.

- 캐시는 `cache_version`이 일치할 때만 사용한다.
- `ct_porosity_threshold`는 캐시에 저장된 원래 측정값에 다시 적용한다.
- 캐시 적중 여부와 무관하게 최종 선택 source는 generate 단계에서 plan의 SHA-256으로 다시 검증한다.
- 캐시 사용은 속도만 바꾸며 output slot, seed, ID, 원본 fingerprint 및 생성 결과를 바꾸지 않는다.

1. `raw_root.resolve()`로 절대경로를 구한다.
2. 경로가 없거나 directory가 아니면 중단한다.
3. `os.walk()` 한 번으로 하위 파일을 열거한다.
4. raw-root 기준 POSIX 상대경로로 정렬한다.
5. 경로 구성요소 전체가 다음 marker와 일치할 때만 원천·라벨로 분류한다.

```python
SOURCE_MARKERS = {"01.원천데이터", "원천데이터"}
LABEL_MARKERS = {"02.라벨링데이터", "라벨링데이터"}
RAW_SPLIT_MARKERS = {"training", "validation"}
```

6. pairing key는 `(raw_split.casefold(), stem.casefold())`이다.
7. image 1개와 JSON 1개인 key만 유효 pair다.
8. image-only, JSON-only, decode 오류, 개별 schema 오류는 source 제외 후 audit에 기록한다.
9. 같은 key에 image 또는 JSON이 복수면 임의 선택하지 않고 전체 실행을 중단한다.
10. 원본 파일은 읽기 전용이며 수정·이동·삭제하지 않는다.

### 4.4 preflight와 전체 audit

preflight:

- Training/Validation × CT/RGB 네 stratum에서 각 25 pair를 검사한다.
- JSON parse, 이미지 decode, 크기, stem, ROI, polygon 형식을 검증한다.
- 같은 오류가 stratum의 20%를 초과하면 전체 스캔 전에 중단한다.

전체 audit:

- 모든 pair의 schema와 이미지 decode를 확인한다.
- SHA-256은 1MiB streaming chunk로 계산한다.
- CT polygon 면적과 bbox는 직렬화 반올림 전 full precision 좌표로 계산한다.
- 제외 사유와 상대경로를 `extraction_audit.csv`에 기록한다.
- 원본 raw fingerprint와 config hash를 generation plan에 저장한다.

### 4.5 plan 생성

1. 유효 source를 modality와 케이스 전제조건별 pool로 분류한다.
2. CT alignment pool은 유효한 battery outline이 있는 CT source만 포함하며 porosity 존재를 요구하지 않는다.
3. CT metal streak pool은 고밀도 anchor mask가 있는 source만 포함한다.
4. RGB glare pool은 outline이 유효한 source만 포함한다.
5. 고정 seed로 output slot과 reserve 순서를 만든다.
6. 신규 battery/image ID 충돌을 raw JSON 전체 ID와 비교한다.
7. PASS/FAIL, failure case, main/test, seed와 ID를 plan에 고정한다.
8. `generation_plan.csv`, raw fingerprint, config SHA-256을 저장한다.

plan 생성만으로 원본 또는 최종 이미지 파일을 만들지 않는다.

### 4.6 generate

각 sample worker는 다음 순서로 실행한다.

```text
1. plan row와 source 상대경로 수신
2. raw-root와 결합하고 path traversal 검사
3. source JSON 한 번 parse
4. source 이미지 한 번 decode
5. CT ROI crop 또는 RGB 전체 frame 준비
6. PASS면 공통 처리만 수행
7. FAIL이면 배정된 failure case의 단계만 수행
8. 기하 증강이면 polygon을 동일 변환
9. 최종 긴 변 512 resize
10. sample staging 폴더에 JPG/JSON 2개 또는 3개 저장
11. 자동 조건, decode, 크기, 좌표, hash 검사
12. 통과하면 최종 경로로 promote
13. manifest record 반환
```

병렬 처리:

```text
effective_jobs = min(
    config.jobs,
    os.cpu_count() or 1,
    memory_safe_jobs
)

memory_safe_jobs =
floor(available_memory × 0.70 / measured_worker_peak_rss)

chunk_size =
max(1, task_count // (effective_jobs × 8))
```

- worker는 manifest나 summary에 직접 append하지 않는다.
- main process가 synthetic image ID 순으로 결과를 정렬해 manifest를 쓴다.
- item seed는 worker 실행 순서와 무관하다.
- worker 오류가 발생하면 staging sample을 공개하지 않는다.

### 4.7 자동 검증과 reserve 교체

1. 각 failure case의 자동 통과 조건을 sample마다 검사한다.
2. 실패하면 결과 파일을 공개하지 않고 `generation_errors.csv`에 기록한다.
3. 같은 failure case의 다음 reserve source로 동일 output slot을 재시도한다.
4. reserve source는 slot의 synthetic ID, 신규 ID, partition, case, seed를 승계한다.
5. `consumed_source_keys`에 이미 존재하는 reserve source는 건너뛴다.
6. reserve 승격이 확정되면 해당 source key를 `consumed_source_keys`에 즉시 추가한다.
7. 같은 case reserve가 소진되면 전체 generate를 실패 처리한다.

### 4.8 sample commit과 resume

PASS는 2개, FAIL은 3개의 파일이 모두 준비된 뒤에만 완료 처리한다.

```text
<output>/.sample_staging/<synthetic_id>/
```

1. staging에 필수 파일을 모두 쓴다.
2. 각 파일을 다시 열어 decode/JSON parse/hash를 확인한다.
3. 최종 위치로 이동한다.
4. `dataset_manifest.csv` 행을 마지막 commit marker로 기록한다.
5. manifest 행이 없는 partial 파일은 완료로 인정하지 않는다.

resume 조건:

- raw fingerprint 동일
- config hash 동일
- generation plan hash 동일
- 기존 manifest의 파일 hash 일치
